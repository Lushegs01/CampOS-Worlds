# Combat Arena audio: pipeline and how to change it

Everything the arena plays is an edit of a real, licensed recording. The pipeline downloads the source packs, edits
them offline (cuts, trims, fades, filters, level, pitch, layers), runs quality checks and writes compressed sound banks
the game loads on demand. The game synthesises one sound only: the tinnitus ring after a flashbang (a fading
pure tone, which is how the ear's ringing is heard).

```
sources.mjs ──► .asset-cache/arena-audio/<pack>/      masters (downloaded, never committed)
recipes.mjs ──► build-arena-audio.mjs (dsp.mjs)      edits, variations, QC
            ──► public/assets/arena/audio/*.mp3       runtime banks (sprites) + manifest.json
            ──► docs/audio/LICENSES.md, qc.json       what was used, from where, and how it measured
inventory.mjs ► docs/audio/INVENTORY.md               every bank, sound and clip
```

| File | Role |
|---|---|
| `scripts/assets/arena-audio/sources.mjs` | The source packs: title, author, licence, page, archive or file list, notes. BigSoundBank recordings are listed by number (`BSB`). |
| `scripts/assets/arena-audio/recipes.mjs` | What every sound is made of: weapon recordings (`FIREARMS`), mechanical parts with time codes (`MECH`, `WEAPON_MECH`), the shared banks (`BANKS`: ui, vo, handling, impacts, explosives, movement), footsteps by surface (`SURFACE_SOURCES`, `LANDINGS`), ambience (`AMBIENCE`), voices (`VOICES`) and breathing (`BREATH`). |
| `scripts/assets/arena-audio/dsp.mjs` | Offline DSP on Float32 PCM: decode/encode with ffmpeg, onset detection, trims, sin² fades, biquads, varispeed, short-term loudness normalisation, seamless loops, clipping detection. |
| `scripts/assets/build-arena-audio.mjs` | The build: download, master (FFSL clipped peaks repaired with `adeclip`), render each recipe, assemble sprites, encode MP3, QC every clip on the decoded MP3, write manifest, licences and QC report. |
| `scripts/assets/arena-audio/inventory.mjs` | Writes `docs/audio/INVENTORY.md` from the manifest and QC report. |
| `src/arena/sound/engine.ts` | Runtime: loads and decodes banks (at their own rate, decoder delay measured from a marker), pools voices with priorities, places sounds in 3D, routes them through category buses, keeps decoded memory within budget. |
| `src/arena/sound/events.ts` | The event table: each kind of sound's category, priority, range, distance curve, voice limits, reverb send and variation. |
| `src/arena/audio.ts` | Game events → sounds: shots, tails, reload and action timelines, footsteps, impacts, reactions, announcer, ambience, UI. |
| `src/arena/sound/{reloads,gait,surfaces,reactions,variation}.mjs` | Pure, unit-tested logic: reload plans shared with the first-person animation, gait phase and cadence, surfaces under a position, hit-reaction rules, shuffle bags. |

## Building

Requirements: Node 20+, `ffmpeg`/`ffprobe` on the path, `unzip`, and `7z` (or Python with `py7zr`) for the Free
Firearm Sound Library archive. The first build downloads about 1.1 GB of masters into `.asset-cache/arena-audio/`.

```bash
node scripts/assets/build-arena-audio.mjs
```

```bash
node scripts/assets/build-arena-audio.mjs w.vanguard impacts
```

```bash
node scripts/assets/arena-audio/inventory.mjs
```

The first command rebuilds every bank, the manifest, `docs/audio/LICENSES.md` and `docs/audio/qc.json`. The second
rebuilds only the named banks (the manifest keeps the others; licences are regenerated by full builds only, so finish
with a full build before committing). The third regenerates the inventory. The build ends by listing any clip flagged by QC; commit only builds with none.

## Banks and clips

A bank is one MP3 sprite (mono, at the bank's rate) plus, for weapons, a stereo sprite (`.st.mp3`, 48 kHz) holding the
close-up shot bodies and tails. Each sprite starts with a one-sample marker at 50 ms; the engine finds it after
decoding to measure the browser's MP3 decoder delay, so clip offsets are exact on every browser. The manifest stores
each clip as `[file, start, duration, peakAt, loop?]`: `peakAt` is when the clip is loudest, which is how a part of a
reload lands on its animation frame (the engine starts the clip `peakAt` early).

Banks load on demand: the interface with the lobby; at deployment the player's loadout, movement, handling, impacts,
explosives, announcer, the soldier's voice and breathing and the map's ambience; footstep banks for surfaces near the
listener; other weapons and voices when a player carrying or using them is seen. Decoded audio has a budget (32 MB on
phones, 96 MB elsewhere); over it the least recently used banks that can come back are let go (never the player's own),
and a weapon whose bank is not ready is stood in for by one of its class.

## Changing or adding a sound

1. **Find the recording.** Use a source with a licence that allows use in a game and modification: CC0, CC BY or
   CC BY-SA (the banks that use CC BY-SA recordings are shared under the same licence, and LICENSES.md lists them).
   Never use ripped game audio or a commercial library without a licence. Add the pack to `sources.mjs` (title,
   author, licence, page, download) or, for BigSoundBank, add its number and title to `BSB`.
2. **Write the recipe** in `recipes.mjs`. A region of a file is `R(src, at, dur, opts)`; a whole file trimmed of its
   lead-in is `W(src, opts)`; `'#k'` as `at` picks the k-th detected onset. Options include `rate` (pitch), `lp`/`hp`
   (filters), `gain`, `fi`/`fo` (fades), `layers` (mix several), `norm: { short: dB }` or `{ peak: dB }`. Give every
   sound at least two variants (footsteps eight); the engine never plays the same one twice running.
3. **Use it.** Weapons pick up `WEAPON_MECH` parts by name in their reload plan (`src/arena/sound/reloads.mjs`); other
   sounds are played from `src/arena/audio.ts` with an event kind from `events.ts` (`play('bank/sound', { ...EV.impact,
   at })`). Add a new event kind there rather than ad hoc levels.
4. **Build and check.** Rebuild the bank, read its rows in `docs/audio/qc.json` (flags must be empty; notes describe
   expected traits), run the full build, `node scripts/assets/arena-audio/inventory.mjs`, `node --test
   tests/arena-audio.test.mjs` and the browser suites below.

### Reload timing

A reload is a plan of named parts at fractions of the simulation's reload time (`RELOADS` in `reloads.mjs`), the same
plan the first-person animation reads (`Scene.tsx`), so a sound's loudest moment lands on the frame where the hand
reaches that point. An empty reload adds the parts a tactical one skips (a dropped magazine, the bolt release or
charging handle). Pump and bolt actions after each shot are cycles (`CYCLES`) driven by the weapon's cooldown. Parts
are scheduled frame by frame and cancelled by tag, so switching weapons or sprinting out of a reload stops them.

### Mixing

Categories (weapons, movement, character, environment, explosions/impacts, interface, announcer) are buses with their
own volume (arena Settings → Sound) feeding a glue compressor and a brick-wall limiter on the arena master, which the
campus Volume scales. The player's own shots and near explosions duck the environment briefly (a near blast also the footsteps); an
announcer line ducks the environment while it plays. Levels:
bank sounds are normalised by short-term loudness to a per-sound target in the recipe; relative levels between event
kinds live in `events.ts`. Check the result with `tests/browser-arena-audio.mjs` (the 3 s firefight must not clip).

## Testing

```bash
node --test tests/arena-audio.test.mjs
```

```bash
VITE_QA=1 npx vite build --outDir dist-qa
```

```bash
node tests/browser-arena-audio.mjs
```

```bash
node tests/browser-arena-audio-match.mjs
```

```bash
node scripts/qa/arena-sounds.mjs
```

Unit tests cover the reload plans, gait, surfaces, reactions and variation. The browser suites play the real game in
Chromium (phone profile, then a desktop Training match against the server's bots) and record every sound the engine
plays, with timing, level and position, plus the output through an analyser; results are written to
`docs/arena-audio-results.json` and `docs/arena-audio-match-results.json`. `arena-sounds.mjs` measures the built
weapon reports (spectra, distinctness between weapons and between a weapon's own variants).
